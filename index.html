Getting Started with Autopsy in Kali Linux

A beginner-friendly walkthrough of launching Autopsy Forensic Browser 2.24, creating a case and host, and adding a practice disk image.

Training demonstration · Kali Linux in Oracle VirtualBox

What is Autopsy?

Autopsy is a digital forensic investigation tool for organizing cases and examining digital evidence. This tutorial documents the classic Autopsy Forensic Browser 2.24 included in the demonstrated Kali Linux environment. It is different from the newer desktop Autopsy application. Investigators can use forensic tools to review disk structures, file metadata, and potentially recoverable artifacts while preserving their original evidence.

Use only disk images and devices that you own or are authorized to examine. This is a training exercise, not a completed forensic investigation.

System requirements

Operating system

Kali Linux virtual machine running in Oracle VirtualBox (as demonstrated)

Software

Autopsy Forensic Browser 2.24, terminal, and a browser such as Firefox

Hardware

Enough memory and storage for Kali Linux and the evidence image; a practical starting point is 4 GB VM RAM and 20+ GB free VM storage, depending on your setup

Evidence

An authorized practice disk image in a format supported by your Autopsy installation

Quick Start Guide

The five figures below come from the actual screenshots captured during this demonstration.

STEP 01

Start Autopsy in Kali Linux

In Kali Linux, open a terminal and run sudo autopsy. The terminal displays the local server address http://localhost:9999/autopsy. Leave the terminal open while using the tool.

STEP 02

Open the forensic browser

Open Firefox inside Kali Linux and visit http://localhost:9999/autopsy. The home screen provides New Case, Open Case, and Help options.

STEP 03

Enter the case information

Choose New Case, then enter a case name, description, and investigator. The screenshot shows the case-entry form before submission.

STEP 04

Create the case and host

After submitting, Autopsy confirms that TrainingCase and its configuration file were created. Next choose Add Host to organize the evidence under a host.

STEP 05

View the added forensic image

The host gallery shows TrainingCase, host1, and an image labeled practice.img-disk with file-system type raw. This confirms the image was registered; it does not yet establish the contents of the image.

Next: analyze the image

In the host gallery, select the radio button next to the image and choose Analyze. If the image contains a recognized file system, inspect available volumes and files, and document only what the tool actually displays. If Autopsy cannot identify a file system, verify the image format and consider using a properly prepared sample image. Capture an additional screenshot of the analysis results before reporting any findings.

For the in-class demonstration, show the running server, open the case, identify the host and image, and explain what you would inspect next.

Conclusion

This exercise demonstrated the first stages of a digital forensic workflow: launching Autopsy, establishing a case, creating a host, and registering a practice image. These steps provide a structured foundation for later evidence examination. The screenshots confirm case setup and image registration; they do not, by themselves, demonstrate file recovery or substantive forensic findings.
